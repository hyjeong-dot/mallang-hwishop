### 주문 상태 (OrderStatus)

```java
public enum OrderStatus {
    PENDING,         // 입금대기 (주문접수)
    PAID,            // 결제완료 (주문완료)
    PREPARING,       // 상품준비중
    SHIPPING_READY,  // 배송준비중
    SHIPPED,         // 발송완료
    CANCELLED        // 취소됨
}
```

### 취소/환불 정책

| 상태 | 취소 가능 여부 | 비고 |
|------|:-------------:|------|
| PENDING | ✅ 1시간 이내 | **1시간 이내 미결제 시 자동 취소 로직 추가** |
| PAID | ✅ 당일만 | Toss 결제 취소 API 호출 (당일 23:59 까지만 취소 가능) |
| PREPARING 이후 | ❌ | 교환/환불 불가 (핸드메이드 특성) |

- **취소 사유 입력**: 
  - 구매자 직접 취소 시: 체크박스 선택(단순변심, 추가 구매 후 재결제 등) 및 텍스트 추가 입력 가능
  - 관리자 취소 시: 기본 체크박스 선택 or 관리자가 직접 취소 사유 텍스트 입력
  - 양측 모두 주문 상세 페이지 및 관리자 주문 관리에서 취소 사유 열람 가능

> 관리자 설정 페이지에서 취소 가능 기간, 교환환불 정책 ON/OFF 가능

## 🚚 합배송 — 최종: B(기존) + A(추가 구현)

- 이미 있는 장바구니 기능 활용

## 🔐 동시성 제어 — 예약 판매 핵심 설계

### 문제 상황

정시 오픈 시 수십~수백 명이 동시에 같은 상품을 구매하려 함.  
재고가 10개인데 11명이 결제하면 안 됨.

### 해결 전략

```
[결제 요청]
    ↓
[트랜잭션 시작]
    ↓
[SELECT stock FROM product WHERE id = ? FOR UPDATE]  ← 비관적 락
    ↓
[stock > 0 && stock >= 요청 수량?]
    ├─ YES → stock 차감 → Toss 결제 승인 → 주문 생성 → 커밋
    └─ NO  → "품절되었습니다" 응답 → 롤백
```

### 체크 포인트

| 시점 | 체크 내용 |
|------|-----------|
| 장바구니 담기 | 재고 > 0 확인 (soft check, 락 없이) |
| 장바구니 페이지 진입 | 실시간 재고 체크 → 품절 상품 알림 |
| 결제 직전 | **이중 검증** — 재고 재확인 |
| 결제 완료 시 | **비관적 락 + 재고 차감** (핵심) |

### maxPerOrder 검증

- 동일 상품에 대해 해당 고객의 **기존 주문 수량 합산** 체크
- (기존 PAID 주문 수량 + 이번 주문 수량) > maxPerOrder → 차단

### 자동 솔드아웃

- stock이 0이 되면 자동으로 `saleStatus = SOLD_OUT`
- 메인 페이지에서 흐리게 표시 + "SOLD OUT" 뱃지

## ⏰ 예약 판매 스케줄러

### 동작

1. 관리자가 상품 등록 시 `saleStartAt` 설정 → `saleStatus = UPCOMING`
2. Spring `@Scheduled` (1분 간격) 또는 정밀 스케줄러가 체크
3. `saleStartAt <= now()` 인 UPCOMING 상품 → `ON_SALE`로 전환
4. 고객 화면: D-Day 카운트다운 표시 (JS `setInterval`)

### 고객 화면 표시

| 상태 | 표시 |
|------|------|
| UPCOMING | "🔔 7/25(금) 오후 8시 오픈" + 카운트다운 |
| ON_SALE | 정상 구매 가능 |
| SOLD_OUT | 흐림 처리 + "SOLD OUT" 뱃지 |
